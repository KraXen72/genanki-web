<Section id="manifest" title="Connect the files">

The manifest connects the pack's files and defines its Anki note type. File paths start from the folder containing `template.toml`.

<Code name="template.toml">{starterFiles['template.toml']}</Code>

<Table label="Manifest options">

| Option | Meaning |
| --- | --- |
| `format_version` | Use 1. |
| `key` | Your template's unique key. Use lowercase letters, digits, and hyphens, starting with a letter. Maximum 64 characters. |
| `input_version` | Start at 1; see “IDs & versions”. |
| `name` | Name shown in the app. |
| `schema` / `prompt` / `css` | File names from the pack files table. |
| `model.id` | Your Anki note type's unique number, from 1 to 9007199254740991. |
| `model.name` | Name shown for this note type in Anki. |
| `destination.policy` | `fixed` or `shared-source`; see below. |
| `destination.deck` | Deck name, such as `Languages::Vocabulary`. Maximum 200 characters; each part needs a name. |
| `fields` | 1–64 fields, each with `name`, `path`, and `format`. `list` also needs `item_path`; `label` needs a `labels` table. |
| `cards` | 1–8 cards, each with a unique name and front/back file names. |
| `tags` | Optional prefix/path mappings from raw strings to `prefix::value` tags. |
| `validators` | Optional content checks: `ru-stress` for Russian stress; `ru-aspect` for verb aspect, partners, and motion. |

</Table>

`shared-source` adds `::Lesson 1` when all notes have `source = "Lesson 1"`, otherwise `::Mix`. `fixed` uses the configured `destination.deck`. Deck name components are trimmed and normalized to Unicode NFC. Each export makes one deck.

Tags use nonempty values without whitespace. Missing optional values produce no tag. Anki reimports can replace existing tags, including tags added by hand.

Validators read the raw values of their named fields together for each note. Errors block export. Review warnings require **Export anyway**; notices allow export immediately.

</Section>

<Table label="Supported JSON Schema keywords">

| Keyword | Meaning |
| --- | --- |
| `$schema`, `title`, `description`, `examples` | Schema version (draft-07), title, description, and examples. |
| `type` | Choose one: object, array, string, integer, number, or boolean. |
| `properties`, `required`, `additionalProperties`, `items` | Fields, required names, and list items. Every object needs `additionalProperties: false`. |
| `const`, `enum` | One exact value (text, number, or true/false), or up to 64 choices. |
| `minLength`, `maxLength`, `minItems`, `maxItems` | Text length and list size. Set `maxLength ≤ 4000` for every string and `maxItems ≤ 2000` for every array. |
| `minimum`, `maximum` | Smallest and largest allowed numbers. |
| `dependencies` | Require related fields together, as below. |
| `pattern` | Use one of the two patterns below. |

</Table>

<Code name="Optional paired fields (inside a note schema)">{`"dependencies": {
  "sentence": ["translation"],
  "translation": ["sentence"]
}`}</Code>

<details class="my-5 rounded-box border border-base-content/15 bg-base-100">
<summary class="cursor-pointer px-4 py-3 font-medium">Supported pattern values (JSON)</summary>

The source pattern blocks `::` and control characters. The plain text pattern blocks em dashes, HTML brackets, Anki expressions, and audio references.

<Section id="fields" title="Map data into Anki fields">

Each `[[fields]]` copies a value from a note into an Anki field. Names must be unique: start with `A–Z` or `a–z`, then use letters or digits. Anki keeps the order you list them in.

<Table label="Field formats">

| Format | Behavior |
| --- | --- |
| `text` | Text, numbers, or true/false. Missing optional values leave the field empty. |
| `lines` | Like `text`, converting line breaks to `<br>`. |
| `list` | Read a list using `item_path`. Adds a `div` per item; see below. |
| `label` | Map a string enum through `[fields.labels]`, then HTML-escape the label. Missing optional values leave the field empty. |

</Table>

`path = "word"` reads the word. `path = "meanings.0.sk"` reads `sk` from the first meaning: counting starts at zero.

<Code name="Nested text mapping (template.toml)">{`[[fields]]
name = "SlovakMeaning1"
path = "meanings.0.sk"
format = "text"`}</Code>

A `label` mapping requires `[fields.labels]` with exactly one label per input enum value, up to 64. Labels live in the pack manifest. The LLM writes enum slugs in its input TOML; the compiler expands them for Anki.

For a few meanings, use separate `text` fields, like the Russian template. Keep layout HTML in the card files so notes stay easy to edit.

<Code name="List mapping alternative (template.toml)">{`[[fields]]
name = "Meanings"
path = "meanings"
format = "list"
item_path = "en"`}</Code>

With `meanings = [{ en = "book" }, { en = "volume" }]`, this creates the HTML below *inside the editable field*. The list must exist. `item_path` names one property and works with `list`.

<Code name="Generated Meanings field">{`<div class="Meanings" style="grid-row: 1">book</div>
<div class="Meanings" style="grid-row: 2">volume</div>`}</Code>

</Section>

<Section id="identity" title="Update your template">

Keep `key` and each note's `id` the same when correcting notes so exported notes keep the same identity. Anki's import settings, local edits, and note-type compatibility affect updates.

The app skips repeated notes with identical IDs, sources, and content. Conflicting source or content under the same ID causes an error. Each imported template needs a unique key and model ID among the loaded packs.

<Table label="Versioning">

| Setting | When to change it |
| --- | --- |
| `format_version = 1` | The pack format this page covers. |
| `input_version` → `template_version` | Increase it when changing required fields or allowed values. Set `template_version` to match in JSON and TOML. The app rejects every other version. |
| `model.id` | Keep it for appearance changes. Changing field/card names, order, or count requires a migration decision. Give each new note type a distinct ID. |

</Table>

</Section>

<Section id="limits" title="Stay within the limits">

<Table label="Resource limits">

| Resource | Limit |
| --- | --- |
| Pack ZIP | 2 MiB zipped; 8 MiB unzipped; 64 files/folders; 512 KiB per file. UTF-8 text only. |
| Pack paths | Keep files inside the template folder. Use relative paths with `/` separators. The loader rejects backslashes, colons, and `.` / `..` folder names. |
| Input schema | 64 KiB; 512 schema entries; up to 12 levels of nesting. |
| TOML batch | 4 MiB; 1–2000 notes. |
| Note ID / source | Nonblank ID: up to 200 characters. Source: up to 100, without `::` or control characters. |
| Anki field | 32 KiB after conversion. |

</Table>
